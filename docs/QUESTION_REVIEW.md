# 신규 문제 추가 & 검수 절차

새 문제를 **안전하게 추가 → 테스트베드에서 검수 → 프로덕션 반영**하는 표준 절차입니다.
프로덕션 사용자는 검수 중인 문제를 절대 보지 않습니다.

## 핵심 개념

- **draft 문제**: `js/data.js`의 항목에 `draft: true`를 붙이면 "검수 대기" 문제가 됩니다.
  - 일반 플레이(모든 환경)에는 **출제되지 않음** → 프로덕션 안전.
  - **테스트베드**(`/preview/`)의 **🧪 검수 모드**에서만 모아서 출제됩니다.
- **검수 모드 버튼**: 테스트베드에서만 보입니다(프로덕션에선 숨김). 신규 문제 개수도 함께 표시.

## 절차 (체크리스트)

### 1) 문제 추가 (개발 브랜치)
`js/data.js`의 `ALBUMS`(또는 멤버/YT)에 새 항목을 추가하고 **`draft: true`**를 붙입니다.
```js
{ id: "spill_the_feels", title: "SPILL THE FEELS", year: 2025, type: "미니 12집",
  titleTrack: "THUNDER", itunes: "SEVENTEEN SPILL THE FEELS", draft: true },
```
> 자켓 이미지는 `scripts/fetch-art.mjs`가 `itunes` 힌트로 채웁니다. 없으면 플레이스홀더로 동작.

### 2) 자동 검증 (CI 게이트)
`node --test` 가 draft 문제를 자동 점검합니다. **하나라도 어기면 CI 실패 → 배포 차단**:
- 필수 필드(`id/title/titleTrack/type`) 존재, `year` 정수
- 4지선다 출제 가능 + 보기에 정답 포함
- 공개 목록(`ALBUMS`)에 draft 유입 없음

### 3) 테스트베드에서 검수 (수동)
개발 브랜치를 푸시하면 자동으로 테스트베드(`/preview/`)에 반영됩니다.
`/preview/` 접속 → 시작화면 하단 **🧪 검수 모드** 클릭 → 신규 문제만 플레이하며 확인:
- [ ] 자켓/사진 이미지가 정상 로드되는가
- [ ] 정답이 실제로 맞는가(오탈자·연도·타이틀곡)
- [ ] 오답 보기가 그럴듯한가(너무 쉽거나 정답이 2개처럼 보이지 않는가)
- [ ] 한/영/일/중/서 로케일 표기가 깨지지 않는가
- [ ] 커버에 앨범 번호가 노출돼 정답이 새지 않는가(`numOnCover` 확인)

### 4) 프로덕션 반영
검수 통과한 문제에서 **`draft: true`를 제거**(또는 삭제)하고 커밋 → 승격(promote) 워크플로 실행.
그때부터 실서비스에 출제됩니다.

## 주기적 운영 팁
- 매주/격주로 "이번 회차 신규 문제"를 draft로 모아 두고, 릴리즈 날 한 번에 검수 → 승격.
- draft를 남겨둔 채 다른 기능만 먼저 승격해도 안전합니다(프로덕션엔 draft가 안 나오므로).

## 관련 코드
- `js/data.js` — `draft` 분리(`splitDraft`), 공개/`DRAFTS` 노출, 테스트 주입 훅(`__SVT_TEST_DRAFTS`)
- `js/game.js` — `review` 모드(테스트베드 전용), 검수 버튼 노출
- `tests/quiz.test.mjs` — draft 검증 게이트 / `tests/e2e.test.mjs` — 검수 모드 노출·출제
