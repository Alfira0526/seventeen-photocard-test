# 주간 업데이트 로드맵 & 제품 방향성

SEVENTEEN 앨범 자켓 퀴즈의 "주 단위 업데이트"를 위한 기획 문서. 5인 페르소나 협의로
방향성·우선순위·리스크를 정리한다. (기획 비전문가도 읽고 판단할 수 있도록 근거 명시)

---

## 0. 최종 산출물 방향성 (North Star)

> **"매달 새로 도전하고, 빠를수록·잘 알수록 인정받고, 매주 새로운 재미가 도는
> 세븐틴 팬 퀴즈."**

네 기둥으로 지탱한다:

| 기둥 | 의미 | 이미 갖춘 것 |
|---|---|---|
| **실력 변별** | 지식 + 속도 + 콤보로 진짜 고수가 상위권 | 새 점수제(속도·난이도·콤보) |
| **시즌 경쟁** | 매달 리셋·매달 챔피언·분기 누적 | 월간 시즌 + 명예의 전당 |
| **주간 신선함** | 이벤트·신규 모드·신규 문제로 매주 방문 이유 | (본 로드맵에서 구축) |
| **바이럴** | 자랑하고 싶은 결과·우승 카드 공유 | 결과 공유카드 + 해시태그 |

주간 릴리스의 목적은 위 4기둥 중 **"주간 신선함"과 "바이럴"을 매주 조금씩 채우는 것**.

---

## 1. 5인 페르소나 협의 요약

- **팀장(8년차)** — 성장기엔 "완성"보다 **릴리스 리듬**이 중요. 매주 1개 테마를 정해 작게
  내보내고 반응을 본다. 큰 기능은 2~3주로 쪼갠다. 아래 우선순위 확정.
- **QA(4년차)** — 신규 모드/이벤트는 **기존 점수·시즌 로직을 깨지 않는지**가 핵심 검증점.
  특히 쿠폰은 "부정 가능성 + 연락 수단 없음"이 최대 리스크.
- **개발자(4년차)** — 정적 사이트 + Firebase 제약 안에서 대부분 **config 기반**으로 구현 가능
  (시즌 스케줄과 동일 패턴). 난이도 선택은 기존 `difficulty` 태그 재사용이라 공수 작음.
- **기획자(4년차)** — 최초 기획의도(자켓·멤버·MV 퀴즈 + 랭킹)를 해치지 않는 선에서 재미 확장.
  난이도 선택·이벤트는 재방문 훅으로 강력. 보상은 "명예 → 실물" 단계적 접근 권장.
- **디자이너(3년차)** — 신규 모드는 **온보딩(첫 선택 UX)**, 보상은 **연출(우승 카드·뱃지)**가
  체감을 좌우. 이벤트는 배너 한 줄로 명확히.

**결론(팀장 종합):** 아래 6주 로드맵으로 진행. Week 1(난이도 선택)과 Week 2(명예 보상)를
먼저 — 공수 대비 체감이 크고 리스크가 낮다.

## 2. 주간 릴리스 로드맵 (v1, 6주)

| 주차 | 테마 | 핵심 항목 | 산출물 | 리스크 |
|---|---|---|---|---|
| **W1** | 난이도 선택 모드 | 일반 모드에 상/중/하 선택 + 난이도 배수 | 신규 모드 1종 | 낮음(태그 재사용) |
| **W2** | 시즌 보상 ①(명예) | 월간 1위 👑 챔피언 뱃지 + 우승 인증 공유카드 | 보상 연출 | 낮음 |
| **W3** | 이벤트 프레임워크 | 시간제 모디파이어(더블포인트 위켄드·컴백 위크) | config 기반 이벤트 v1 | 중(시간대·로케일) |
| **W4** | 콘텐츠 확장 | 신규 문제 유형(가사 한 줄·안무 포인트 등) + 오답률 높은 문제 점검 | 문제 풀 확장 | 중(데이터 검증) |
| **W5** | 시즌 보상 ②(실물) | 우승 청구 플로우 + 최소 연락 수집 + 프라이버시 | 쿠폰 지급(재원 확보 시) | **높음**(개인정보·부정·재원) |
| **W6** | 소셜/바이럴 | 친구 대결(2인 점수 비교)·우승 카드 개선 | 공유 강화 | 중 |

> 매주 릴리스는 기존 **주간 운영 리뷰 루틴**(docs/OPS_ROUTINES.md)과 연동 — 그 주에 들어온
> 오류 제보·이용률·정답률을 함께 반영한다.

## 3. 신규 모드: 난이도 선택 (상·중·하) — W1 상세

**설계**
- 시작화면 '가볍게 한 판'에 난이도 칩 추가: **쉬움 / 보통 / 어려움**.
- 문제 풀을 기존 `difficulty`(1~4) 태그로 필터:
  - 쉬움 = 1~2 / 보통 = 2~3 / 어려움 = 3~4.
- **랭킹은 분리하지 않는다**(작은 유저풀을 또 쪼개면 판이 썰렁 — 기존 "모드 분리 지양" 원칙과 일관).
  대신 **난이도 배수**로 통합 랭킹 유지: 예) 쉬움 ×0.8 · 보통 ×1.0 · 어려움 ×1.3.

**왜 배수인가 (QA 관점)**
- "쉬움만 골라 고득점" 악용 방지. 어려움일수록 점수가 커야 상위권 경쟁이 공정.

**체감(디자이너)**
- 첫 진입 시 난이도 툴팁 1줄("자신 있으면 어려움! 점수가 더 커요").

**공수:** 소 — 문제 생성부(questions.js)에 난이도 필터 파라미터, 점수식(game.js)에 배수 1개.

## 4. 시즌 1위 보상(쿠폰) — 단계적 접근

**핵심 리스크 3가지 (개발자·QA)**
1. **연락 수단 없음** — 현재 랭킹은 *이름만* 저장. 우승자에게 쿠폰을 보낼 방법이 없다.
2. **부정 가능성** — Firebase 공개 쓰기라 점수 조작이 이론상 가능. 실물 보상이 걸리면 표적이 됨.
3. **재원** — 쿠폰 비용 출처(스폰서/자체)가 정해져야 한다.

**그래서 2단계로 나눈다**

- **1단계 · 명예 보상(W2, 즉시·무비용)**
  - 월간 1위에게 **👑 'O월 챔피언' 뱃지**를 명예의 전당에 영구 박제(이미 챔피언 박제 구조 있음).
  - **우승 인증 공유카드** 자동 생성(SNS 자랑용). 개인정보·재원 불필요.
  - → 대부분의 동기부여는 여기서 발생. 팬덤은 "명예/인증"에 강하게 반응.

- **2단계 · 실물 쿠폰(W5, 재원 확보 시) — '도전 이벤트' 모드로 처리**
  - 실물 보상은 상시 랭킹이 아니라 **도전 이벤트가 열렸을 때 그 기간의 점수만 모으는 전용 모드**에서
    진행한다(대상·기간을 명확히 한정 → 공정성·관리 용이).
  - 그 모드 안에서 **사용자 동의 하에** 연락처(전화번호 또는 이메일)를 받는다(경품 발송 목적, **선택**).
  - 수집 데이터는 **개인정보보호법(PIPA) 준수**로 보안 처리:
    - 동의 없이는 수집 안 함 · **최소 수집** · **목적 명시**(경품 발송 전용)
    - **목적 외 사용·제3자 제공 금지** · **암호화 저장** · **보관 기간 경과 시 파기** · 개인정보처리방침 고지
  - **부정 검증**: 상위 기록 수동 확인(운영 리뷰 루틴에서). 의심 기록은 제외.
  - 쿠폰 재원은 스폰서 제휴 또는 소액 자체 예산.

  > 흐름: `도전 이벤트 시작(기간 지정) → 기간 한정 점수 집계 → (동의) 연락처 입력 →
  > PIPA 준수 보안 처리 → 부정 검증 → 우승자 보상 지급`

**권장:** 1단계부터 시작. 트래픽·반응을 보고 2단계 여부·규모 결정.

## 5. 이벤트 프레임워크 (W3)

시즌 스케줄(season.js)과 동일한 **config 기반 시간제 모디파이어**.

- **더블 포인트 위켄드** — 주말 동안 점수 ×2.
- **컴백 위크** — 신보 발매 주간, 해당 앨범 문제 가중 출제 + 배너.
- **앨범 집중 주간** — 특정 앨범만 몰아서(테마 퀴즈).
- **출석/연속 방문** — 가벼운 리텐션 훅(선택).

배너 한 줄로 노출("⚡ 이번 주말 더블 포인트!"). 종료 시각도 시즌처럼 카운트다운.

## 6. 운영 연계

- 매주 릴리스 전, **주간 운영 리뷰 루틴** 산출물(docs/ops/SNAPSHOT.md)을 확인해
  그 주 오류·이용률·정답률을 반영한다.
- 신규 모드/이벤트도 텔레메트리(analytics.js)로 이용률을 계측 → 다음 주 우선순위 근거.

## 7. 사용자(운영자) 결정 필요 항목

1. **쿠폰 재원** — 실물 보상(2단계)을 갈 것인가? 재원 출처(스폰서/자체)?
2. **개인정보 범위** — 실물 보상 시 수집할 최소 정보(이메일만? SNS DM?)와 프라이버시 정책 수위.
3. **난이도 배수 값** — 쉬움/보통/어려움 배수(초안 0.8 / 1.0 / 1.3) 확정.
4. **주간 릴리스 순서** — 위 6주 순서를 그대로 갈지, 이벤트(W3)를 앞당길지.

> 1·2번은 사업/법무 판단이라 운영자 결정이 필요하고, 3·4번은 제안값으로 바로 진행 가능.
